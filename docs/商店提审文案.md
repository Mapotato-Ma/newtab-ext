## 0 · 这一版（0.4.0）改了什么

- **左侧文件夹竖栏**替换原来的顶部胶囊栏（分组一多，胶囊要换行占三行）
- **索引卡**替换原来的小磁贴：图标 + **完整标题（不截断）** + 站点域名
- **多级子文件夹**：钻取 + 面包屑，任意深度都收得住；每层可就地折叠
- 修掉一个旧版真 bug：**只渲染两层，但计数和搜索含全部层级**（第 3 层往后的书签根本没显示）
- 设置里新增：**每行列数（1–4 列）**、**字体大小 6 档（12–24px）+ 字重 3 档**、文件夹计数口径（含子层 / 只算本级）
- 左栏悬浮预览统一成「所有分组都有」：**固定居中 + 毛玻璃面板**，两列最多 24 条、可滚动，
  每条带图标和域名，有子文件夹先亮名字
- 设置面板点页面别处即可关闭；面板贴右上角齿轮的左下角，限高 + 内部滚动
- 左栏悬浮预览可关闭（设置里的开关，默认开）
- **图标会跟着字号一起缩放**（图标大小 = 图标档位基准 × 字号倍数）；滚动条全站统一
- **权限没有任何变化**（还是 bookmarks / favicon / storage + 两个建议接口的域），商店那页不用重填
- 三张商店截图已按新 UI 重做（2026-10-14），旧的留在 `shots-old-0.3.3/`

```

**类别**：`生产力工具`　**语言**：`中文（简体）`

**详细说明**

```
把浏览器里本来就有的书签，换成一个真正好用的新标签页。

■ 它是什么
不是又一个「书签管理工具」。它就是你的书签栏本身 —— 你在 Chrome 里加一条书签、改个名字、挪个位置，新标签页立刻跟着变。不需要注册、不需要导入、不需要同步，因为数据本来就是 Chrome 自己的。

■ 分组
书签栏里的一级文件夹 = 左侧竖栏里的一行（严格按你自己的顺序，绝不重排），右侧是这一组的索引卡：图标 + 完整标题 + 站点域名。方向键切换分组（到头绕回），Home/End 跳首尾。

■ 多级子文件夹
书签文件夹可以嵌套很多层，这里用「钻取 + 面包屑」接住任意深度：点开子文件夹就往下走一层，顶部面包屑永远告诉你现在在哪、点任意一段就能跳回去，Esc 返回上一级。每一层都能就地折叠展开。计数默认包含子层（可在设置里改成只算本级）。

■ 搜索框
右上角可以直接搜。点左边的放大镜在必应和谷歌之间切换；输入时给建议下拉 —— 线索里会先出现你自己书签里匹配的条目（带图标和域名），再是搜索引擎的网络建议。↑↓ 选择、回车打开。

■ 图标
走 Chrome 自己的图标缓存。某个网站真的没有图标时，用书签标题的第一个字当图标，颜色由域名算出来 —— 不会出现一排难看的灰色问号。

■ 其它
· 界面缩放 90%～150%（Ctrl/⌘ + +/− 也能调）
· 深色 / 浅色 / 跟随系统
· 打开方式：新标签页或当前标签页
· 时间显示到秒或到分
· 每行 1～4 列、字体大小与字重、文件夹计数口径、左栏悬浮预览开关

■ 隐私
不收集、不上传、不存储你的任何数据。没有账号系统，没有后端服务器，没有统计代码。
书签只在本地读取用于显示（只读，不会修改或删除你的书签）；界面偏好存在 Chrome 自带的账号同步里。
你唯一会「发出去」的东西，是你在搜索框里输入的那几个字 —— 它直接发给对应搜索引擎的建议接口，和你自己在搜索网站输入是一样的。

完整说明见隐私政策。
```

```

## 4 · 隐私标签页怎么填

**单一用途说明**（Single purpose）

```
把用户已有的 Chrome 书签渲染成一个按文件夹分组的新标签页，并在其上提供一个搜索入口。
```

**权限用途说明**（每一项都要单独填，逐条复制）

`bookmarks`

```
读取用户的 Chrome 书签（文件夹结构与网址），用于在新标签页上渲染分组网格。扩展对书签只有只读访问，不会创建、修改、移动或删除任何书签，也不会上传书签内容。
```

`favicon`

```
向 Chrome 本地的图标缓存查询每个书签对应网站的图标，用于在卡片上显示。图标来自本机缓存，该权限不会让扩展向任何网站发送请求。
```

`storage`

```
保存用户的界面偏好（主题、界面缩放、打开方式、搜索引擎）。使用 chrome.storage.sync，数据由 Chrome 自带的账号同步功能管理，扩展没有服务器，作者无法访问这些数据。
```

`https://api.bing.com/*`

```
当用户在新标签页的搜索框中输入文字时，向必应的搜索建议接口请求候选词并显示在下拉框中。只发送用户输入的那段文字，不发送书签、浏览历史或任何其它数据。
```

`https://suggestqueries.google.com/*`

```
同上，用于用户把搜索引擎切换为谷歌时的搜索建议。同样只发送用户输入的那段文字。
```

> ⚠️ **主机权限只能填一个框时，用下面这段合并版**（否则必应那段会丢）：
>
> ```
> 为两个搜索建议接口申请主机权限：
> · https://api.bing.com/* —— 当用户在新标签页的搜索框中输入文字时，向必应的搜索建议接口请求候选词并显示在下拉框中。
> · https://suggestqueries.google.com/* —— 同上，用于用户把搜索引擎切换为谷歌时的搜索建议。
> 两处都只发送用户输入的那段文字，不发送书签、浏览历史或任何其它数据。
> ```
> 如果页面给的是两个独立框（每个域名一个），就保持上面两段分开填，别合并。

**「您正在使用远程代码吗？」** → 选 **「不，我并未使用远程代码」**

我们所有的 JS 都随扩展包发布：没有外链 `<script>`、没有外部模块、没有 `eval`、没有动态代码求值。
下面那个「理由」框是给选了「是」的人用的，**不用填**；如果它标着必填卡住不让过，填：

```
扩展的全部 JavaScript 均随扩展包一同发布，未引用任何外部脚本、外部模块，也不使用 eval 或动态代码求值。
```

**数据使用声明**

· 「此扩展程序是否收集用户数据」→ **否**
  （按 Chrome 的定义：数据没有离开设备就不算收集。书签只在本地读取，界面偏好走 Chrome 自带同步，
  扩展作者没有任何服务器接收数据。）
· 下面三条承诺（**我不会出售/传输给第三方、不会用于与单一用途无关的目的、不会用于判定信用**）
  → **三个都要勾**。这题是反向表述，勾上才是"承诺不做"（表单明确写了：三个全选才符合开发者计划政策）
· 9 类数据类型 → **全部不勾**（书签只在本地读、从不上传；界面偏好走 Chrome 自带同步，我们没有服务器，
  按 Chrome 的定义"数据没离开设备就不算收集"）
· 在附加说明里主动写明这一句，免得审核来回问：

```
用户在搜索框输入的文字会直接发送给用户选择的搜索引擎（必应或谷歌）的建议接口，
用于显示搜索建议。除此之外，扩展不向任何地方发送数据；书签与浏览历史一律不外发。
```

## 6 · 隐私政策怎么更新

**源文件在扩展仓库里**：`newtab-ext/privacy.html`。改完同步到 Pages 仓库再推：

```bash
cp /var/minis/workspace/newtab-ext/privacy.html /var/minis/workspace/newtab-privacy/index.html
cd /var/minis/workspace/newtab-privacy && git add -A && git commit -m "docs: 隐私政策更新" && git push
# 等约 1 分钟，复核 https://mapotato-ma.github.io/newtab-privacy/
```

仓库：`Mapotato-Ma/newtab-privacy`（GitHub Pages，`.nojekyll` 已在）。
⚠️ `mapotato.fun/privacy/newtab.html` 那份是**镜像**，商店里填的是 Pages 地址；两份内容要一起改。

## 7 · 以后怎么更新

```bash
cd /var/minis/workspace/newtab-ext
sed -i 's/"version": "0.4.0"/"version": "0.4.1"/' manifest.json   # 改版本
python3 build.py                                                    # 重新打包（自带校验）
```
然后把新的 zip 传到开发者控制台即可 —— 所有装了它的机器（包括以后的 Mac）会**自动升级**，不用你动手。

> 想再省一步的话，Chrome 有 **Publish API**：配好一次 OAuth 之后，我可以直接从服务器把新版本推上去，
> 连「打开控制台点上传」都省了。等商店那边跑顺了你再说要不要配。
