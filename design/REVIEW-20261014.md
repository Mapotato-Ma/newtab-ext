# MiniMax《文件夹原生约束 · 排版预案》评审 + 嵌套规格

评审对象：`design/20261014-minimax-folder-layout-plan.html`（MiniMax 出的排版预案）
评审时间：2026-10-14 · 评审人：Minis（技能 `impeccable`，critique 流程）
被审项目：`newtab-ext` v0.3.3「索引卡 · 新标签页」

## 一句话结论

排版层面这稿子**基本可以直接照做**（保序、单行省略、计数右对齐这些都是对的）；
但它在两个地方踩空：**一个数据拿不到（时间列），一个只有鼠标能用（悬停预览）**；
另外它画的「嵌套」只是两层，7 层的完整规则要补（见下）。

## 一、直接采用（照做）

1. **左栏保序** —— 严格按 Chrome 文件夹顺序，任何情况下不重排。
   他自己 21 个组的顺序是手动排的（AI → 常用 → token中转站 → 环境 …），重排 = 毁掉空间记忆。
2. **名称单行 + 省略 + 悬停全称** —— 行高恒定，不做折行。
   实测他的名字跨度极大：`token中转站`(12 字无空格) / `归档 · 2026-10`(含空格间隔号) / `PRD原型图`(拉丁紧贴汉字)。
3. **计数等宽右对齐、固定列宽** —— 长短名字不推挤数字。这条现在的胶囊栏没做到。
4. **空组原地置灰、不移动不隐藏** —— 计数 0 只降透明度。
5. **左栏独立滚动 + 自动滚入可见区；超 40 组顶部加筛选框**（筛选 ≠ 排序）。
6. **明确不做的五条**我都同意：按数量/频次重排、自动改名打标签、折叠左栏、**在左栏做多层树形展开**。
   21 项树状导航确实扫视不了 —— 这条正好是下面嵌套方案的前提。

## 二、三处要改 / 要砍

1. **「时间列」（12:40 / 昨天 / 2 天前）拿不到数据 —— 建议直接砍。**
   现在 `manifest.json` 的权限是 `bookmarks` / `favicon` / `storage`。书签 API 只给 `dateAdded`
   （加入时间），**不给最后访问时间**；要显示"12:40 / 昨天"必须申请 `history` 权限。
   代价：① 商店重新审核、权限弹窗多一项；② 一个"只读书签"的扩展去要浏览历史，信任成本不值。
   → 保留列表排版可以，时间那一列删掉。
2. **「计数 ≤5 悬停浮出内容」只有鼠标能用 —— 改成 hover + focus 双通道**，且浮层要能 Esc 关、
   内部最多显示 ~8 条再内部滚动（否则 5 条长标题就顶出屏幕外）。
3. **脚注自己承认部分数据是示例**（`待整理 2026-11` / `公司 0` / `精选网站 0`）；
   21 组里哪几个是真的、哪几个是编的，要看真实书签才知道。别把它当既定事实用。

## 三、嵌套（0–7 层）怎么展示 —— 你问的那个问题

**先说一个已确认的真 bug**（MiniMax 的「待确认」我替它确认了）：
现在的代码**只渲染两层，但计数和搜索含全部层级**。

- `newtab.js` 的 `groupSection()`：对每个子文件夹只取 `inner.items` 渲染，`inner.subs` 被丢掉
  → **第 3 层往后的书签根本不在页面上**。
- `groupTotal()` / `flattenAll()` 却是递归的 → 左栏和页脚的计数包含所有层级，
  搜索也能搜到那些看不见的书签。
- ⇒ 所以他那个「543 是否含所有层级」的问题答案是：**含**。数字没错，是**内容没画出来**。
  这既是排版问题也是渲染问题，实现时必须一起修。

### 方案：三层视觉 + 钻取面包屑（屏幕上的层级感恒定，永不随数据深度增长）

**规矩一：左栏永远只列第 1 层。** 第 2 层及以下全部在主区表达。
（这条直接继承他"不在左栏做树"的结论。）

**规矩二：主区从上到下永远是这三档，无论数据几层：**

1. **面包屑**（钉在主区顶部）：`全部 / AI / 图像生成 / Midjourney`，每段可点，末段后跟计数。
2. **当前层的直属书签** → 磁贴网格。
3. **直接子文件夹**，每个一个**小标题条**（文件夹图标 + 名称 + `n 项` + `›`），
   小标题条下面铺它的内容；**它自己还有子文件夹时，只在条下缩进 1 格显示入口行**，
   不继续往下铺 → 想看就点进去（面包屑变长一位）。

屏幕上的视觉层级**永远只有 3 档**：当前层内容 ＞ 子文件夹小标题 ＞ 更深层入口行。
所以第 7 层和第 2 层走的是同一条路，**代码里不要为深度写任何特例**。

**规矩三：缩进刻度只画 2 格。** 更深的层级不靠缩进表达，一律靠面包屑 —— 缩进 7 次会把文字挤没。

**规矩四：面包屑溢出折叠。** 深度 ≥ 4 时中间收成 `…`（保留第一层 + `…` + 最后两层），
点 `…` 展开完整路径。

**规矩五：计数语义统一为「含所有更深层级」**（与现有 `groupTotal` 一致），
子标题条上的 `n 项` 同理。设置里加开关「计数只算本级」放 v2。

**规矩六：空的深层文件夹不渲染**（与左栏"空组置灰不隐藏"是**有意的例外**）：
左栏空组保的是用户手动排的空间记忆；深层空文件夹只是噪声。

**规矩七：安全阀。** 递归到第 8 层停止，并在面包屑显示 `…n 层未展开`（Chrome 不会成环，但代码要防）。

## 四、键盘与状态（左栏一上，旧模型必须一起改）

- 现在：`←→↑↓` 都是切分组。改左栏后：**左栏有焦点时 `↑↓` 切组**，`←→` 仍保留为切组（老习惯不丢）。
- **`Esc` = 返回上一级**（面包屑变短一位）；已经在顶层则不动。
- 主区的子文件夹小标题条：`Tab` 可达、`Enter` 进入；面包屑每段 `Tab` 可达。
- 状态持久化：`localStorage` 记住「上次看的分组 + 它在那个分组里钻到哪一层」，
  下次开新标签页原样回去（现在是只记分组名）。

## 五、实现计划（下一步动手时照这个走）

1. **数据模型**：`buildGroups` 从「{items, subs} 两层」改成**递归节点树**
   `{id, name, path[], items[], subs[], total}`（`total` 含所有层级）。
2. **渲染**：`groupSection` 改递归 + 引入「当前路径」状态；新增面包屑、子文件夹小标题条两个组件。
3. **样式**：`newtab.css` 加左栏 / 面包屑 / 子标题条 / 缩进刻度 / 深色三套；沿用现有 CSS 变量。
4. **交互**：键盘模型（上面第四节）、左栏筛选框、hover+focus 预览浮层。
5. **验证**：
   - `preview.html` 的假数据里**塞一条 7 层深的链**，逐层点进去截图核对（浅色 + 深色各一轮）；
   - 边界：0 项文件夹、超长名（`design-system-tokens`）、中英混排、50 个顶层文件夹；
   - 真机：装进他的 Chrome 看真实 21 组 + 真实嵌套深度。
   - ⚠️ `impeccable detect` 在 iSH 上跑不了（二进制 `Illegal instruction`），
     检查退化为「渲染截图肉眼过两轮 + 手动核对规则」。
6. **交付**：版本 0.4.0 → `python3 build.py` → zip；商店更新流程见 `shared/newtab-ext-store/submit.md`。
